**As an** authenticated user without a pair, **I want to** connect with exactly one other person using a one-time invite code, **so that** we share a private space that no third person can join, no matter what.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → joinPair (HTTPS callable) | Untrusted inviteCode string from browser; authenticated via Firebase Auth token |
| Client → createPair (HTTPS callable) | Authenticated UID only; no user-supplied data except auth token |
| Cloud Function → Firestore | Trusted writes via Admin SDK; bypasses security rules |
| Client → Firestore (direct) | Blocked by security rules for all pair mutations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-01 | Spoofing | createPair / joinPair callables | mitigate | `if (!request.auth) throw HttpsError('unauthenticated')` — first check in both functions (ASVS V2) |
| T-02-01-02 | Tampering | Client writes pairId directly to users/{uid} | mitigate | Firestore rule: `!request.resource.data.diff(resource.data).affectedKeys().hasAny(['pairId'])` (already in rules — preserve) |
| T-02-01-03 | Tampering | Client writes to pairs/{pairId} | mitigate | Firestore rule: `allow write: if false` on pairs/{pairId} — all mutations via Cloud Functions only |
| T-02-01-04 | Elevation of Privilege | Invite code brute-force (16M hex codes × 24h window) | mitigate | App Check `enforceAppCheck: true` on both callables (SEC-07); emulator does not enforce by default — production App Check is the gate |
| T-02-01-05 | Elevation of Privilege | Race condition: two users submit same invite code simultaneously | mitigate | `inviteCodeUsed` check inside Firestore transaction — second committer's transaction aborts atomically |
| T-02-01-06 | Elevation of Privilege | Creator attempts to join their own pair | mitigate | `if (pair.createdBy === uid) throw HttpsError('invalid-argument')` inside transaction |
| T-02-01-07 | Elevation of Privilege | Already-paired user creates a second pair | mitigate | `if (userSnap.data().pairId !== null) throw HttpsError('already-exists')` inside createPair transaction (PAIR-06) |
| T-02-01-08 | Information Disclosure | Partner's user doc readable via Firestore rules `get()` | accept | Rule requires requester to be a member of the target user's pair — only legitimate pair members can read; `members` is server-written only |
| T-02-01-SC | Tampering | npm/pip/cargo installs | accept | Phase 2 adds zero new packages; all dependencies are pre-existing and verified in Package Legitimacy Audit |
</threat_model>
