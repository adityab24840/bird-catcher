  <read_first>

    - .planning/phases/03-submissions-privacy-layer/03-RESEARCH.md §6 — SubmitEntrySchema field definitions (Zod 4 syntax)

    - CLAUDE.md §Zod 4 — confirm `z.url()` is top-level (not `z.string().url()`) in Zod 4
  </read_first>
  <action>
    Create `shared-reveal/tests/unit/submissions.test.ts`. The schema must be inlined in the test file (same approach as `pair.test.ts` inlines `JoinPairSchema`) so the test has no dependency on the functions build.

    Inline `SubmitEntrySchema` using Zod 4 syntax:
    - `z.object({...}).superRefine(...)` — outer schema + at-least-one refinement
    - `entryDate: z.string().regex(/^\d{4}-\d{2}-\d{2}$/)` — YYYY-MM-DD format
    - `text: z.string().max(500).nullable()` — max 500 chars, nullable
    - `photoURL: z.url().nullable()` — top-level `z.url()` (Zod 4), nullable
    - `.superRefine()` adds a `z.ZodIssueCode.custom` issue on path `['photoURL']` when both `photoURL` and `text?.trim()` are falsy

    Test cases to include — two `describe` blocks:

    `describe('SubmitEntrySchema')`:
    - `'accepts photo + text'` — both non-null → `result.success === true`
    - `'accepts photo only (text null)'` — `text: null`, `photoURL` URL → success
    - `'accepts text only (photoURL null)'` — `photoURL: null`, text non-empty → success
    - `'accepts exactly 500 chars of text'` — `'x'.repeat(500)`, `photoURL: null` → success
    - `'rejects both null (at-least-one)'` — `photoURL: null, text: null` → failure; `result.error?.flatten().fieldErrors.photoURL` is defined
    - `'rejects whitespace-only text'` — `photoURL: null, text: '   '` → failure
    - `'rejects text longer than 500 chars'` — `'x'.repeat(501)` → failure
    - `'rejects invalid photoURL'` — `photoURL: 'not-a-url'` → failure
    - `'accepts entryDate YYYY-MM-DD format'` — `'2026-08-31'` → success
    - `'rejects entryDate YYYYMMDD format'` — `'20260831'` → failure

    `describe('Date computation (SUBM-07)')`:
    - `'toLocaleDateString("en-CA") produces YYYY-MM-DD'` — construct `new Date('2026-08-31T12:00:00')`, call `.toLocaleDateString('en-CA')`, expect match on `/^\d{4}-\d{2}-\d{2}$/` and exact value `'2026-08-31'`

    `describe('Idempotent submission guard (SUBM-04)')`:
    - `'submittedMembers.includes(uid) detects duplicate'` — `['uid-alice'].includes('uid-alice')` → `true`
    - `'submittedMembers.includes(uid) allows new submission'` — `['uid-alice'].includes('uid-bob')` → `false`

    All imports: `import { describe, it, expect } from 'vitest'` and `import { z } from 'zod'`
  </action>
