Output: A working Playwright config + reusable auth fixture + a passing spec that reaches the authenticated home screen.
</objective>

- The fixture targets the Auth emulator at 127.0.0.1:9099 (matching firebase.json). Do NOT call `connectAuthEmulator` inside `page.evaluate` — firebase/config.ts already connects at app init time when `VITE_FIREBASE_AUTH_EMULATOR_HOST` is set via the webServer env block; calling it again throws in SDK v12. The fixture must only call `signInWithCustomToken`.
- The Admin SDK (firebase-admin) runs in the Node/test process only — never bundled into the app (keeps T-01-06 mitigation from plan 01-02 intact).
- Emulators must be running for the E2E suite: `firebase emulators:start --only auth,firestore,functions`. Document this run order in the SUMMARY and as a comment in playwright.config.ts. The dev server is started by Playwright's `webServer` block.
- Set the emulator env for the test run (.env.test or webServer env): VITE_FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099, VITE_FIRESTORE_EMULATOR_HOST=127.0.0.1:8080, so firebase/config.ts (plan 01-02) connects to emulators.
- Assumption A5 (RESEARCH.md): the Admin SDK against the emulator may not need real service-account credentials — when `FIREBASE_AUTH_EMULATOR_HOST` is set in the Node process, `initializeApp({ projectId })` with the default/emulator credential is sufficient to `createCustomToken`.
