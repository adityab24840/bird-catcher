  signOutUser(): Promise<void>        — calls signOut(auth)

<constraints>
- Firebase SDK v12 modular imports ONLY (e.g. `import { signInWithRedirect } from 'firebase/auth'`). No compat layer (RESEARCH.md State of the Art).
- authDomain MUST be the custom Hosting domain, read from `import.meta.env.VITE_FIREBASE_AUTH_DOMAIN`. Never hardcode *.firebaseapp.com (SEC-08, Pitfall 1).
- Use `signInWithRedirect` (NOT `signInWithPopup`) unconditionally — popup is blocked in iOS standalone (RESEARCH.md Pattern 3, Pitfall 5).
- Call `getRedirectResult()` on app load (in useAuth mount effect) to capture the redirect return (RESEARCH.md Pattern 3).
- User document is created SERVER-SIDE by the Auth onCreate Cloud Function via the Admin SDK — never client-side (avoids the token-hydration race; RESEARCH.md Pitfall 4).
- Cloud Function: use v2 `beforeUserCreated` from `firebase-functions/v2/identity` as primary; if that import path fails at deploy, fall back to v1 `user().onCreate` from `firebase-functions/v1/auth` (RESEARCH.md Pattern 4, Open Question 2, Assumption A4). Document which was used in the SUMMARY.
- Firestore init with `persistentLocalCache({})` for offline persistence and session restore across refresh (AUTH-03, RESEARCH.md Pattern 3).
- Emulator wiring: when `import.meta.env.VITE_FIREBASE_AUTH_EMULATOR_HOST` is set, call connectAuthEmulator and connectFirestoreEmulator (needed by plan 01-04 E2E).
</constraints>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Firebase Auth | OAuth redirect flow crosses to Google and back via /__/auth/handler |
| client → Firestore | Client reads/writes users/{uid}; rules are the authority |
| Auth event → Cloud Function | Server-side user doc creation runs with Admin privileges |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Spoofing | OAuth state / authDomain bypass | mitigate | Custom authDomain on own Hosting domain; only /__/auth/handler allowlisted as redirect URI (SEC-08, Task 1) |
| T-01-04 | Tampering | Client writes pairId directly to users/{uid} | mitigate | firestore.rules (plan 01-01) blocks client writes to pairId via affectedKeys check |
| T-01-05 | Elevation of Privilege | Auth token not ready at first Firestore write | mitigate | User doc created server-side by Auth onCreate Cloud Function; client never races (AUTH-02, Pitfall 4) |
| T-01-06 | Information Disclosure | Admin SDK credentials leaking to client | mitigate | Admin SDK lives only in functions/ (server); never imported into src/ |
</threat_model>
